# Інформаційна система контролю стану музейних експонатів

**Курсова робота з дисципліни «Кросплатформене програмування».**\
Студент: Шеремета Артур Михайлович, група 201-ТН, варіант №24, 2026–2027 н. р.

Це навчальний клієнт–серверний застосунок для обліку **експонатів, оглядів, заявок на консервацію та фахівців**. Для чотирьох сутностей реалізовано CRUD через HTTP/JSON. Бізнес-логіка, валідація, обчислення інтегрального показника і допустимість переходів станів виконуються **на сервері**.

## Склад проєкту

- `database.sql` — база `museum_exhibits`, таблиці, зв’язки та тестові записи.
- `server/` — Maven WAR для **Java 21 / Servlet 4 / Tomcat 9**, Service, DAO/JDBC, MySQL.
- `server/src/test/java/.../CourseworkTest.java` — **30 модульних тестів JUnit 5** (не потребують бази даних).
- `client/` — окремий JavaFX 21 Maven-проєкт, HTTP-клієнт, таблиці й форми CRUD.
- `client/sample-data/exhibits.csv` — контрольний CSV для імпорту каталогу.
- `client/src/main/java/.../task/ImportExhibitsTask.java` — фоновий JavaFX Task і повідомлення про помилки.

### Архітектура

```
JavaFX GUI -> HttpMuseumClient -> HTTP/JSON -> Servlet -> Service -> DAO/JDBC -> MySQL
                  ^                                               |
                  +---------------- JSON response ----------------+

CSV -> JavaFX Task -> HttpMuseumClient -> Servlet -> Service -> DAO/JDBC -> MySQL

```

У клієнті немає SQL, JDBC та паролів до MySQL.

За замовчуванням сервер використовує `root` із порожнім паролем на `localhost:3306`, як у типовому локальному XAMPP. Якщо конфігурація інша, вкажіть **змінні середовища для процесу Tomcat** (не додавайте пароль у GitHub):

```

MUSEUM_DB_USER=root
MUSEUM_DB_PASSWORD=YOUR_LOCAL_PASSWORD

```

На Windows змінні можна задати в конфігурації запуску Tomcat у IntelliJ (Environment variables) або у відповідному способі запуску Tomcat. Не зберігайте справжні паролі в коді.

## 5. Запустити Apache Tomcat 9

Зупиніть Tomcat перед оновленням WAR. Найпростіший спосіб: скопіюйте `server/target/museum-exhibits-server.war` у `TOMCAT_HOME/webapps/` і запустіть Tomcat 9 через `bin/startup.bat` (Windows) або `bin/startup.sh` (macOS/Linux). Tomcat зазвичай працює на порту **8080**. У IntelliJ можна налаштувати конфігурацію Tomcat 9 із WAR.

У браузері перевірте:

- `http://localhost:8080/museum-exhibits-server/exhibits`
- `http://localhost:8080/museum-exhibits-server/inspections`
- `http://localhost:8080/museum-exhibits-server/requests`
- `http://localhost:8080/museum-exhibits-server/specialists`

Відповідь повинна бути JSON-масивом. Якщо з'являється HTTP 500, перевірте MySQL, пароль і журнал Tomcat.

## 6. Запустити JavaFX-клієнт

Відкрийте **новий** термінал із кореня курсової (сервер не вимикайте):

```
cd client
mvn javafx:run
```

Відкриється вікно з чотирма вкладками:

1. **Експонати** — інвентарний номер, назва, матеріал, місце, F1 і F3; кнопки Додати / Змінити / Видалити / Оновити.
2. **Огляди** — ID експоната, дата `РРРР-ММ-ДД`, оцінка F2 і опис огляду.
3. **Заявки на консервацію** — ID експоната, ID огляду, необов’язковий ID фахівця, стан і автоматично розрахований показник I.
4. **Фахівці** — ПІБ, спеціалізація, контакт.

**Важливо:** перед редагуванням, видаленням чи зміною стану виберіть запис у таблиці. Ідентифікатори пов'язаних записів можна подивитися у відповідних вкладках.

Якщо шлях/порт сервера нестандартний, задайте у процесі запуску клієнта змінну середовища `MUSEUM_API_BASE` (наприклад, `http://localhost:8080/museum-exhibits-server`).

## 7. Розрахунок та стани заявки

Числові фактори в діапазоні 0–100:

- **F1** — чутливість матеріалу (`exhibit.sensitivity_score`);
- **F2** — тяжкість пошкодження (`inspection.damage_score`);
- **F3** — значущість експонування (`exhibit.exhibition_score`).

Сервер розраховує:

```
I = 0.40 × F1 + 0.35 × F2 + 0.25 × F3
Приклад F1=80, F2=60, F3=40 → I=63.00

```

Значення I записується в заявці як **знімок оцінки під час створення або редагування**. Якщо змінити експонат або огляд, раніше створена заявка не перераховується автоматично, доки її не відредагувати. Це варто врахувати під час опису системи.

Дозволений порядок:

```
НОВА (NEW) -> ОЦІНЕНО (ASSESSED) -> РОБОТИ (IN_PROGRESS) -> ЗАВЕРШЕНО (COMPLETED)

```

Перестрибувати стан, повертатися назад або повторювати той самий перехід заборонено. Рішення ухвалює серверний `ConservationRequestService`. Завершену заявку не можна редагувати (видалення реалізовано окремо як CRUD-операцію).

## 8. Фоновий CSV-імпорт

У вкладці «Експонати» натисніть **Імпортувати CSV**; типовий файл — `client/sample-data/exhibits.csv`. Кнопка «Обрати CSV» дозволяє вибрати інший файл. Формат:

```
inventory_number;title;material;location;sensitivity_score;exhibition_score
M-001;Старовинна ваза;кераміка;Зал 1;80;40
M-002;Гравюра XIX століття;папір;Фондосховище;90;70
M-003;Срібний кубок;срібло;Зал 3;70;60
```

Рядки обробляються фоновим `ImportExhibitsTask`, кожний надсилається серверу через HTTP. Користувач бачить прогрес, повідомлення та підсумок «додано / пропущено». Помилки окремих рядків (зокрема повторний інвентарний номер) накопичуються, але **не зупиняють** імпорт наступних рядків. Критична помилка читання файлу чи заголовка завершує Task із помилкою. **Не імпортуйте CSV повторно, якщо потрібно продемонструвати успішне додавання: унікальні номери викличуть пропуски.**

## 10. HTTP API

| **Маршрут**    | **GET**        | **POST** | **PUT `?id=N`** | **DELETE `?id=N`** |
| -------------- | -------------- | -------- | --------------- | ------------------ |
| `/exhibits`    | список/`?id=N` | створити | змінити         | видалити           |
| `/inspections` | список/`?id=N` | створити | змінити         | видалити           |
| `/requests`    | список/`?id=N` | створити | змінити         | видалити           |
| `/specialists` | список/`?id=N` | створити | змінити         | видалити           |

Тіла POST/PUT — `application/json`, результати й помилки — JSON. Для зміни стану заявки: `POST /requests?id=N&action=transition`, JSON `{"state":"ASSESSED"}`. HTTP 400 означає помилку даних/заборонений перехід, 404 — відсутній запис, 409 — конфлікт ключів чи станів, 500 — несправність сервера/БД. Видалення через GET **не використовується**.
